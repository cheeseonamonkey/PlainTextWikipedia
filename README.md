# PlainTextWikipedia

Convert Wikipedia into one enriched, article-level Parquet dataset per language.
One workflow, one argument (the language prefix). Source text is preserved; the
feature pass never removes articles.

## Output

Each language build produces a verified bundle of **three files**:

| File | Contents |
|---|---|
| `articles.parquet` | One article per row: original text, a native 180-d fastText embedding, per-article TF-IDF (stemmed, L2-normalized against the language corpus), raw word counts, and grouped JSON statistics |
| `corpus-profile.json` | Language-level context: shared 12 000-term vocabulary with TF/DF/IDF, per-field moments and percentiles, fastText centroid |
| `manifest.json` | Schema version, article count, fastText/lexical configuration, file checksums |

The 13-column article schema and every computation are specified in
[docs/article-features.md](docs/article-features.md).

## Build and publish

- **One workflow:** [Build Wikipedia language dataset](.github/workflows/wikipedia.yml).
  Dispatch it with `language: en` (or `zh`, `es`, `simple`, `enwiki`, …).
  Build-only is the default; the verified bundle is retained as an artifact.
- **Publish:** set `publish: true` to push the verified bundle to Hugging Face,
  Kaggle and Zenodo. Each publisher runs as an independent parallel job — one
  failing never cancels or blocks the others, and the summary job reports all
  three outcomes.
- **Fresh dump:** set `rebuild: true` to convert current Wikimedia dumps instead
  of reusing the dataset's published source shards (also used automatically when
  existing sources are missing or unverifiable).
- **Batch:** the workflow accepts `workflow_call`, so a fleet dispatcher can run
  it as a matrix over many languages.

## Feature knobs

Dispatch inputs: `vocab` (default 12 000), `dim` (180), `window` (8),
`epoch` (1). fastText trains on the shared stemmed vocabulary with no subword
hashing (CBOW, wider context window).

## Retired paths

The multi-file bundle (articles.txt.xz, features.zip, models.zip), Bekko
embeddings, BM25, and the legacy per-shard structured exports have been removed;
the old workflows were consolidated into `wikipedia.yml` and
`rebuild-shards.yml`. Historical artifacts remain on the older dataset versions
and on the previous git tags.
